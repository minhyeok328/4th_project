# 화면 구성

[프론트엔드](README.md) · [템플릿](templates-components.md)

## 공통 구성

[base_page.html](../../templates/base_page.html)을 확장하고 도메인별 partial을 include합니다. Tailwind·DaisyUI 기반 카드·버튼에 검색 필터와 모바일 viewport CSS를 보완합니다. 화면 데이터는 SSR context, API 주소·CSRF·현재 상태는 템플릿의 data 속성으로 전달합니다.

| 화면 | 구현된 상호작용 | 별도 확인하거나 미연결인 부분 |
|---|---|---|
| 메인 | 5종 카테고리 링크, LG봇 진입 | 외부 이미지 로드·반응형 |
| 검색 | 옵션 JSON, 필터 칩, 범위 입력, GET 제출, 페이지 이동 | 잘못된 URL 조건과 옵션 로드 실패 |
| 상세 | 사양·탭·찜 | 구매 서버 없음, 리뷰·Q&A 예시 |
| 채팅 | 질문·히스토리·방 삭제·모바일 사이드바 | 401 재로그인 유도·장문 성능 |
| 로그인 | 세션 폼·클라이언트 입력 검증 | 비밀번호 찾기 API 없음 |
| 회원가입 | 사용자명·비밀번호·닉네임·사진 | 서버 검증과 중복 ID 오류 |
| 마이페이지 | 프로필 수정·찜 제거·개수 갱신 | 파일 업로드 실패·빈 목록 |

## 비동기 상태

채팅은 전송 중 입력을 잠그고 로딩 말풍선을 표시합니다. 찜은 상품 코드별 in-flight Set과 버튼 상태를 사용합니다. 검색 필터 옵션은 로딩·오류 배너를 표시하고 폼 중복 제출을 방지합니다. 이런 클라이언트 제어는 서버의 동시 요청 정합성을 보장하지 않습니다.

## 변경 시 확인할 연결

- 필터 필드 변경: 모델, 필터 JSON, 템플릿 name, URL 직렬화를 함께 확인합니다.
- API 계약 변경: [ApiResponse와 페이지 모듈](client-javascript.md)의 성공·실패 처리를 함께 확인합니다.
- DOM 구조 변경: data 속성, 전역 onclick 함수, 빈 목록·개수 갱신 셀렉터를 확인합니다.
- 모바일 변경: CSS만으로 결론 내리지 말고 실제 키보드·터치·사이드바 동작을 확인합니다.

과거 개선 판단은 [1차 기록](frontend-test-report.md)과 [2차 기록](frontend-final-report.md)에 보존합니다. 현재 기능 검증은 [검증과 한계](../10-quality/verification-and-limitations.md)를 따릅니다.
