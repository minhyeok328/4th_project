# 검증과 한계

[문서 홈](../README.md)

## 현재 검증 근거

이 문서는 코드·설정·기존 기록을 구분하여 설명합니다. 이번 문서 정리에서 애플리케이션 서버, 브라우저 E2E, 외부 모델·Pinecone 호출을 실행하지 않았습니다.

| 근거 | 확인할 수 있는 범위 |
|---|---|
| 코드·템플릿·설정 | 구현 경로·입출력·설정 존재 여부 |
| [프론트 1차 기록](../03-frontend/frontend-test-report.md) | 해당 시점 정적 분석 |
| [프론트 2차 기록](../03-frontend/frontend-final-report.md) | 해당 시점 정적 분석과 미검증 항목 |
| [모델 평가 기록](model-evaluation-history.md) | 범위·후속·제품군 노드의 소규모 예제 결과 |

5개 앱의 `tests.py`는 기본 생성 상태이며 작성된 테스트 케이스가 없습니다. Node 패키지에도 테스트 스크립트가 없습니다. `python manage.py test`의 종료 상태만으로 기능이 검증되었다고 판단할 수 없습니다.

## 개발 환경에서 실행할 확인

환경변수와 외부 클라이언트 초기화 조건을 [개발 환경](../01-getting-started/development-environment.md)에서 먼저 확인합니다.

```powershell
python manage.py check
python manage.py showmigrations
python manage.py test
```

별도 `theme/static_src` 디렉터리에서 `npm run build`로 CSS 생성을 확인합니다. 위 명령은 재검증 절차이며 이 문서가 실행 성공 결과를 대신하지 않습니다.

## 알려진 한계

- 구매·결제, 비밀번호 재설정, 실제 리뷰·Q&A 저장은 미구현입니다.
- 상품 데이터는 저장된 수집 자료이며 실시간 가격·재고를 보장하지 않습니다.
- `send_chat`은 JSON 최상위 객체 여부와 외부 서비스 예외를 모두 사용자 오류로 정규화하지 않습니다.
- 레거시 찜 API는 비POST 응답이 없고 마이페이지 찜은 상품 존재를 확인하지 않습니다.
- 찜 중복 unique 제약, 대화 메시지 순서 제약, 한 턴 전체 트랜잭션이 없습니다.
- 조건 병합은 빈 조건을 생략합니다. 찜·매뉴얼 코드 목록이 비었을 때 의도한 범위 제한이 유지되는지 확인해야 합니다.
- RAG는 유사 청크 5개와 페이지 복원 최대 20개 청크를 사용하며 매뉴얼 전체·정확한 모델·인용의 완전성을 보장하지 않습니다.
- 챗봇의 전체 메시지 재렌더링과 동기 모델 호출은 긴 대화·지연 상황에서 별도 성능 검증이 필요합니다.
- 운영 비밀키·호스트·정적 파일·서버·복구 구성은 [배포 조건](../09-deployment/deployment.md)에 정리된 준비가 필요합니다.

## 기록 원칙

새 결과에는 실행 명령, 환경, 커밋, 입력 자료, 성공·실패 범위와 실행 날짜를 남깁니다. 노드 분류 정확도, 정적 분석의 Pass, 웹 기능 통합 성공은 서로 다른 근거입니다.
